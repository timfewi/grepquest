# GrepQuest UI Explore

Read the repository instructions and the shared
[project context](../grepquest-ui/references/project-context.md). Inspect relevant
product source, current UI, copy, and real assets before proposing a direction.

Require a clear design target and intended user outcome. Ask one concise question only
when either is missing; infer secondary details from repository evidence.

For net-new or materially redesigned surfaces, produce exactly three visual directions
that use the same product truth and core content. Make them differ in composition,
density, typography, signature interaction, and emotional register—not merely accent
color. Each direction must state:

- its thesis and one memorable signature element;
- palette roles, typography roles, layout logic, and image/capture strategy;
- the first viewport and primary-action hierarchy;
- desktop and mobile behavior;
- motion and reduced-motion behavior;
- its strongest benefit and most important tradeoff.

Use image generation for visual mockups when the tool is available and the user wants
visual exploration. Use real supplied or captured product imagery as references. If
the requested output is prose-only, provide concise art-direction boards instead.

Reject any direction that could be reused unchanged for an unrelated developer tool.
Spend visual boldness in one place and keep surrounding structure disciplined. Use
interface copy that is concrete, active, and consistent with the action it triggers.

Do not scaffold a site or modify product source during exploration. Present the three
directions in comparable form and wait for the user to select or combine one before
handoff to `grepquest-ui-build`.
